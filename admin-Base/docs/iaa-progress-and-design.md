# IAA 激励广告解锁：当前进度与设计方案

## 1. 文档说明

本文档记录 IAA 激励广告功能的业务规则、技术设计和实际落地状态。

当前服务端核心流程、播放权益、管理后台记录和接口文档均已实现。当前项目仍是演示环境，不直接调用 TikTok 广告服务；小程序端应接收 TikTok `onClose` 回调后调用本文定义的服务端接口。

## 2. 当前完成进度

### 2.1 应用与管理后台

应用支持两种互斥的变现类型：

- `IAA`：通过观看激励广告解锁单集。
- `IAP`：通过 Beans 支付或会员订阅解锁。

管理后台已支持变现类型列表、筛选、新建和编辑；IAA 应用可配置广告位 ID。存在支付订单、订阅、永久权益或广告会话时，服务端禁止直接切换变现类型。

### 2.2 小程序接口

小程序应用列表已返回：

- `monetizationType`：`IAA` / `IAP`。
- `adPlacementId`：IAA 激励广告位 ID，未配置时为空。

广告解锁已提供创建、完成和取消会话接口。逐集状态、单集播放和观看上报已识别 `ad` 权益；未解锁集不返回真实 `videoUrl`。

### 2.3 数据与后台记录

- 新增广告解锁会话及 `pending/completed/canceled/expired` 状态机。
- 永久权益支持 `beans/ad` 来源，并按“应用 + 用户 + 剧集 + 集数”唯一。
- 后台用户详情的“永久解锁”记录同时展示 Beans 订单与广告单集权益。
- 观看记录可展示 `ad` 解锁来源。

### 2.4 文档与验证状态

统一小程序接口合同已同步至 `admin-Base/docs/mini-api.md`。代码格式化、后端测试和前端构建验证结果以本次开发最终执行结果为准。

## 3. TikTok 广告完成回调结论

`onClose({ isEnded })` 是 TikTok 小程序前端 JSAPI 回调，不是服务端回调。

只有满足以下条件，才表示用户完整观看了激励广告：

```javascript
isEnded === true
```

推荐处理方式：

1. 小程序前端展示 TikTok 激励广告。
2. 前端接收 `onClose` 回调。
3. 当 `isEnded === true` 时，前端调用本系统服务端的广告完成接口。
4. 服务端校验广告解锁会话并发放剧集解锁权益。
5. 当 `isEnded !== true` 时，不发放权益。

TikTok 激励广告没有直接通知本系统服务端“用户已经完整观看”的业务回调。因此，即使是正式项目，也需要小程序前端接收 TikTok 回调后，再向业务服务端上报结果。

当前项目是演示项目，不实际调用 TikTok 广告接口，前端可以模拟“观看成功”和“观看未完成”两种结果，但仍需按照正式业务流程调用服务端。

## 4. 已确定的业务规则

### 4.1 基础规则

- 付费卡点之前的集数为免费集。
- IAA 小程序不使用 Beans 支付和会员订阅。
- IAP 小程序不使用广告解锁。
- 用户每完整观看一次激励广告，永久解锁当前指定的一集。
- 广告未完整观看、广告加载失败或用户中途关闭时，不发放解锁权益。
- 已解锁集数再次观看时，不需要重复观看广告。
- 解锁权益按照“用户 + 小程序 + 剧集 + 集数”维度记录。

### 4.2 免费集

付费卡点之前的集数直接返回免费解锁状态，不需要创建广告解锁会话。

建议统一使用以下解锁来源：

- `free`：免费集。
- `subscription`：会员订阅解锁。
- `beans`：Beans 支付解锁。
- `ad`：激励广告解锁。

### 4.3 广告解锁

- 一次广告只对应一个目标集数。
- 广告解锁成功后，该集对当前用户永久有效。
- 不允许通过一次广告同时解锁多集。
- 创建会话时已经解锁的集数，应直接返回已解锁结果，不重复创建有效会话。
- 完成上报只能依据服务端保存的会话发放权益，不能信任前端重新提交的用户、剧集或集数。

## 5. 完整业务流程

1. 用户进入 IAA 小程序并选择某部剧集。
2. 小程序获取用户在该剧中的逐集解锁状态。
3. 用户点击未解锁集数。
4. 小程序请求服务端创建广告解锁会话。
5. 服务端校验小程序、用户、剧集、集数和当前权益状态。
6. 服务端创建状态为 `pending` 的广告解锁会话。
7. 服务端返回会话编号、广告位 ID 和过期时间。
8. 小程序根据广告位 ID 展示 TikTok 激励广告。
9. 前端接收 TikTok `onClose` 回调。
10. 当 `isEnded === true` 时，前端调用广告完成接口。
11. 服务端以事务方式将会话更新为 `completed`，并写入该集解锁权益。
12. 小程序刷新当前剧集解锁状态。
13. 服务端返回该集为 `ad` 解锁。
14. 小程序开始播放该集，并正常上报观看记录。

未完整观看时：

- 不调用完成接口；或者调用取消接口，将会话更新为 `canceled`。
- 当前集数继续保持未解锁状态。
- 用户再次点击时，可以重新创建新的广告解锁会话。

## 6. 接口方案

### 6.1 创建广告解锁会话

```http
POST /api/mini/ad-unlock-sessions
```

请求示例：

```json
{
  "userId": "364978937844994048",
  "dramaId": "358554131406786560",
  "episodeNo": 3
}
```

服务端校验：

- 小程序必须为 `IAA`。
- 用户必须存在，并且属于当前小程序。
- 剧集必须存在且已经上架。
- 集数必须存在。
- 目标集数必须位于需要解锁的范围。
- 目标集数尚未被免费、广告或其他有效权益解锁。
- 应用需要配置可使用的广告位 ID。

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "sessionNo": "AD365012345678901248",
    "status": "pending",
    "dramaId": "358554131406786560",
    "episodeNo": 3,
    "adPlacementId": "ad7571338400453756984",
    "expireAt": "2026-08-27T15:30:00+08:00",
    "unlockType": "locked",
    "isUnlocked": false
  }
}
```

### 6.2 完成广告观看并解锁

```http
POST /api/mini/ad-unlock-sessions/:sessionNo/complete
```

完成接口还需要提交 `userId`，用于当前无 Token 的小程序 API 校验会话归属；小程序、剧集和集数均从服务端保存的会话中读取。

```json
{ "userId": "364978937844994048" }
```

服务端处理：

- 会话不存在时拒绝处理。
- 会话已取消或已过期时拒绝处理。
- 会话已完成时幂等返回原有成功结果。
- 使用数据库事务更新会话状态并写入解锁权益。
- 解锁权益已存在时，不重复写入，但仍可幂等返回成功。

### 6.3 取消广告解锁会话

```http
POST /api/mini/ad-unlock-sessions/:sessionNo/cancel
```

该接口用于记录用户中途关闭广告、广告加载失败或其他未完成原因。请求体同样必须携带当前 `userId`，服务端校验会话归属。

取消后：

- 会话状态更新为 `canceled`。
- 不发放解锁权益。
- `canceled` 为终态，不能再更新为 `completed`。

## 7. 数据库方案

### 7.1 广告解锁会话表

建议新增 `ad_unlock_sessions` 表：

| 字段 | 说明 |
| --- | --- |
| `id` | 数据库主键 |
| `session_no` | 广告解锁会话编号，全局唯一 |
| `app_id` | 小程序 ID |
| `user_id` | 用户 ID |
| `drama_id` | 剧集 ID |
| `episode_no` | 目标集数 |
| `ad_placement_id` | 创建会话时使用的广告位 ID 快照 |
| `status` | `pending`、`completed`、`canceled`、`expired` |
| `active_key` | `pending` 目标唯一键；终态清空，用于并发创建保护 |
| `created_at` | 会话创建时间 |
| `completed_at` | 完整观看并解锁时间 |
| `expire_at` | 会话过期时间 |

状态规则：

- `pending` 可以变为 `completed`、`canceled` 或 `expired`。
- `completed`、`canceled`、`expired` 均为终态。
- 终态之间不允许互相转换。

### 7.2 用户解锁权益

优先复用当前用户剧集解锁明细表，并将解锁来源扩展为 `ad`。

建议建立唯一约束：

```text
user_id + app_id + drama_id + episode_no
```

唯一约束可以保证前端重复上报、网络重试或并发请求时，同一集只产生一条有效解锁权益。

## 8. 现有功能需要扩展的范围

### 8.1 剧集详情及解锁状态

逐集状态需要识别广告解锁，并向前端返回：

- 是否已解锁。
- 解锁来源是否为 `ad`。
- 未解锁时是否允许通过观看广告解锁。

### 8.2 剧集播放

播放接口需要将广告解锁权益视为有效播放权限。未解锁的 IAA 付费集不能返回可播放资源。

### 8.3 观看上报

用户开始播放广告解锁集时，观看记录的解锁方式记录为 `ad`。未解锁集数不能播放，因此不存在未解锁观看上报。

### 8.4 IAA 与 IAP 互斥

服务端必须执行最终校验：

- IAA 应用调用 Beans 下单或订阅接口时拒绝处理。
- IAP 应用调用广告解锁接口时拒绝处理。

前端隐藏入口只能改善交互，不能替代服务端业务校验。

## 9. 幂等、并发与安全规则

- 完成接口必须支持重复调用并返回一致结果。
- 完成会话和写入权益必须位于同一个数据库事务中。
- 会话编号必须全局唯一且不可预测。
- 完成接口不能接受前端传入的目标集数作为权益依据。
- 服务端必须校验会话所属用户，避免使用其他用户的会话解锁。
- 过期会话不能完成。
- 同一用户对同一集同时发起多个会话时，只允许生成一条最终权益。
- 演示项目可以信任前端模拟的完整观看结果，但应保留会话和状态机结构，使后续接入真实 TikTok 广告时不需要重写核心解锁逻辑。

## 11. 当前阶段结论

IAA 服务端核心流程已实现：广告会话创建后由小程序展示广告，完整观看时完成会话并永久解锁一集，未完成时取消或等待过期。逐集权限、播放、观看记录和后台永久解锁记录均已接入 `ad` 来源。

当前演示项目的安全边界仍需注意：TikTok 完成结果由小程序前端上报，且 `/media` 为公开静态目录。正式环境应进一步采用可信的广告验证能力（若平台提供）以及签名 URL 或受保护的媒体代理。
